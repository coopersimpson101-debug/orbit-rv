# Contributing

Thanks for looking! Ground rules:

1. **Every RTL change keeps lockstep green.** Run the unit tests and the
   riscv-tests on the RTL with ISS lockstep before sending a PR:

   ```sh
   pip install -e ".[dev]"
   python -m pytest -q tests
   python tools/run_riscv_tests.py --dir build/riscv-tests --sim rtl --lockstep
   ```

2. **The ISS is the reference.** If RTL and ISS disagree, find out which one
   is wrong against the RISC-V specifications before changing either.
   Behaviour the spec leaves to the implementation (Svade, misaligned traps,
   no PMP, ...) must stay identical in both and be listed in
   `docs/microarchitecture.md`.
3. **Numbers come from runs.** Any IPC, utilisation or timing number in the
   docs must be regenerated by the tools (`tools/perf_table.py`,
   `fpga/ulx3s.py`) and labelled as simulation or hardware.
4. Python style: PEP 8, 100 columns. Commit messages: imperative subject line.
